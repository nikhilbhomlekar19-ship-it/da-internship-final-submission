# Test plan and results

**Read this first.** Two kinds of evidence appear below and they are kept apart on purpose:

* **Measured by the author in a Linux sandbox** (real, reproducible with `pytest`, files in `tests/results/`) - covers the SQL *logic*, the model's internal consistency and file validity.
* **To be measured by you** (needs SQL Server, Power BI, ADF) - the suites are written and generated; the result cells are empty. **No SQL Server, Power BI or ADF performance number in this repository was measured by the author.** Fill the tables in yourself.

## 1. Strategy

| Level | What is checked | How | Where | Status |
|---|---|---|---|---|
| L1 Logic | Every dimension/fact SELECT: grain, joins (no fan-out), key lookups, cost-by-date, allocations, snapshots | The shipped T-SQL SELECTs are transpiled and **executed in DuckDB on the real AdventureWorks data**, then compared with an **independent pandas implementation** of the business rules | `tests/test_pipeline.py`, `tools/harness.py`, `tools/compute_baselines.py` | **Run: 89 passed** |
| L2 Data quality gate | 52 checks (48 ERROR, 4 WARN): grain unique, no orphan keys, reconciliation to staging, sign checks | Same SQL that ships in `sql/09_dq_checks.sql`, executed in DuckDB; on SQL Server it runs on every ETL | `tests/test_pipeline.py::test_dq_check`, `tests/sql/01_integrity.sql` | **Run in DuckDB**; SQL Server: *yours* |
| L3 Static | T-SQL syntax; ADF reference integrity; no secrets; generated files in sync | sqlglot (tsql), JSON walk, hash check | `tests/test_static.py`, `tools/lint_sql.py` | **Run: 8 passed** |
| L4 Power BI files | 108 JSON files vs Microsoft's published schemas; 58 measures' table/column/measure references; 178 report field references; TMDL indentation and relationships | jsonschema + custom linters | `tools/validate_model.py` | **Run: 0 errors** (not opened in Desktop) |
| L5 Warehouse on SQL Server | 49 KPI baselines (±cents), staging = source row counts, DW = source totals | T-SQL | `tests/sql/02_kpi_baselines.sql`, `03_source_reconciliation.sql` | **Yours** |
| L6 Semantic model | 55 DAX tests (49 KPI + 6 RLS with impersonation) on the published model | `executeQueries` REST API | `tests/dax/run_dax_tests.ps1` | **Yours** |
| L7 Performance | ETL duration, refresh duration, page load, DAX query time | step_log, Refresh history, Performance analyzer | section 5 | **Yours** |

## 2. Results measured in the sandbox

`tests/results/sandbox_pytest.txt` - `97 passed, 1 skipped` (the skip is the dim_date alias check: that table is generated by a hand-written proc, not a SELECT). `tests/results/sandbox_static_checks.txt` - generated files up to date; T-SQL lint **114 batches parsed, 3 command-only (ALTER DATABASE / synonyms / GRANT-DENY, not parsed by sqlglot), 0 errors**; Power BI validation **108 files valid, 0 invalid; 58 measures; 178 report field references; 0 errors**. `tests/results/sandbox_warehouse_build.txt` - DuckDB built the whole warehouse from the real files in about 2-4 s (reference only, **not** a SQL Server timing).

### Mutation check (do the tests catch bugs?)
Six bugs were injected one at a time into a copy of the repo; the suite must go red.

| Injected bug | Caught by |
|---|---|
| Cost-history join loses its upper date bound (row fan-out: 121,317 → 169,049 lines) | `test_row_counts` |
| Freight allocated with the *tax* column | `test_freight_allocation_reconciles` |
| Fiscal year starts in August | `test_net_sales_by_fiscal_year` |
| COGS ignores cost history | `test_net_sales_cogs_margin` |
| Purchase territory lost (RLS-critical) | `test_unknown_members_not_overused` |
| On-time rule `<` instead of `<=` | **not caught - equivalent mutant**: no PO line ships exactly on its due date in this data, so no data-based test can tell the two apart |

So **5 of 5 detectable mutants were caught**. One earlier version of the HR-by-region baseline was empty (string-vs-int join) and the test passed vacuously; it is fixed and every baseline loop now asserts its expected size.

## 3. How to run your part

```bash
# SQL Server (after scripts/setup_local.*):
SQLPASSWORD=... ./scripts/run_sql_tests.sh          # writes tests/results/sql_tests_<timestamp>.txt
# Power BI (after publishing):
pwsh tests/dax/run_dax_tests.ps1 -WorkspaceId <guid> -DatasetId <guid>      # writes tests/results/dax_results.md/.json
# anywhere with Python:
python tools/build_repo.py --check && python tools/validate_model.py && pytest -q tests
```
